## Правки macOS (центрирование заголовка + VPN-гейт запуска Zapret)

### 1. Заголовок раздела строго по центру (нативный macOS-вид)
`src/renderer/src/components/base/base-page.tsx`: разметка верхней панели
разветвлена по `isMac`. На macOS название раздела (`props.title`)
позиционируется `absolute left-1/2 -translate-x-1/2` — СТРОГО по центру
всей ширины окна, корректно при любом размере (resize). Трафик-лайты
рисуются в App.tsx поверх слева (`top-3 left-5`) и не пересекаются.
Кнопка «назад» (если `showBackButton`/subpage) — `absolute left-20`, чтобы
не налезать на трафик-лайты. Windows оставлен БЕЗ изменений (исходный
`justify-between`: заголовок слева, WindowControls справа).

### 2. VPN-гейт запуска Zapret (фикс «краша» при VPN+запрет)
ПРИЧИНА краша: запуск Zapret (pf + utun50) ПОВЕРХ живого VPN-туннеля ломает
сетевой стек macOS → туннель/IPC/сетевые вызовы в невалидном состоянии.
Фикс — не выполнять НИКАКИХ сетевых операций, если VPN активен.

- Новый файл `src/main/utils/vpn.ts`: `isVpnActive(): VpnCheck` —
  `{status:'active'|'inactive'|'unknown'}`. Нативная детекция macOS,
  НЕ привязанная к конкретному интерфейсу:
  1) `scutil --nc list` → `(Connected)` (системные VPN: IKEv2/L2TP/PPTP/
     Cisco IPSec, сетевые расширения вкл. офиц. WireGuard);
  2) `scutil --nwi` → «Active interfaces» (сторонние VPN через utun/tun/ppp,
     напр. OpenVPN/Tunnelblick);
  3) `ifconfig -l` фолбэк (любой поднятый utun/tun/ppp).
  Свой интерфейс Zapret (`utun50`) исключён из детекта. Никакого curl/IP-сервиса.
  Функция НИКОГДА не бросает (spawn-ошибки/nil/пустой вывод/неожиданный
  формат → `unknown`/`inactive`), поэтому сама детекция не может уронить приложение.
  `VPN_BLOCK_MESSAGE = 'VPN включён. Запрет невозможно запустить при активном VPN.'`
- `src/main/core/zapret-macos.ts` `startZapretImpl`: сразу после проверки
  `isWinwsRunning()` (и ДО `isInstalled()`/`restart.sh`) — на macOS зовём
  `isVpnActive()`. При `active` → `setStatus({state:'error',lastError:VPN_BLOCK_MESSAGE})`
  и `throw` (без трогания pf/utun). При `unknown` → `log('warn', …)` и
  ПРОДОЛЖАЕМ запуск (ложный запрет хуже краша); при `inactive` → как раньше.
- Постоянного статуса VPN в UI НЕТ (по требованию) — сообщение только
  транзиентно при попытке старта с VPN вкл. Рендер: `isDeniedError()` НЕ
  матчит «Запрет» (matчит «запрещ»), поэтому баннер/свитчер показывают
  ровно VPN_BLOCK_MESSAGE, а не VPN_HINT_MESSAGE.
