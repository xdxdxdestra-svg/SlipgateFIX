## Исправления macOS (tgws + zapret)

### TgWsProxy: "Failed to load Python shared library … different Team IDs" (exit 255)
Причина: `electron-builder` → `@electron/osx-sign` подписывает **каждый** бинарный
файл внутри `Contents/` (walkAsync + цикл по children), а `hardenedRuntime` в
electron-builder применяется **ко всем файлам**, не только к .app. У вложенного
PyInstaller-onefile `resources/tgws/TgWsProxy` включается library validation →
встроенный в архив Python.framework (другой Team ID) не проходит dlopen.

Решение:
- `src/main/utils/mac-binary.ts` (новый): копия бинарника в writable runtime-каталог
  (`<userData>/runtime/prepared/`) + `chmod 755` + `xattr -d com.apple.quarantine`
  + `codesign --force --sign -` (ad-hoc, без hardened runtime → library validation off).
  Правим копию, НЕ файл внутри .app (иначе ломается печать бандла → "app is damaged").
- `build/entitlements.mac.plist`: добавлен `com.apple.security.cs.disable-library-validation`
  (этот же файл идёт как `entitlementsInherit`, т.е. для вложенных бинарников).
- `tgws.ts`: подготовка перед spawn; хвост stdout/stderr теперь попадает в `lastError`
  (раньше было только "exited with code 255"); stop на mac добивает через `pkill -9 -f TgWsProxy`
  (PyInstaller onefile оставляет дочерний процесс).
- `tgws-updater.ts`: на macOS отсекаются ассеты `.dmg/.zip/.pkg/...` (upstream публикует
  для mac только `TgWsProxy_macos_universal.dmg` с GUI .app — писать его поверх бинарника
  нельзя); после записи — `fixMacBinaryInPlace`.

### ZapretMac: «Zapret не установлен на Mac»
Причина: `installZapretBundle` отрезал только верхний каталог `ZapretMac.app/`, поэтому
payload оказывался в `<runtime>/zapret/Contents/Resources/Payload/…` и
`/bin/sh '<dest>/install.sh'` не находил файл; результат `runAsAdminOnMac` игнорировался
(она возвращает `{code,out}`, а не бросает) → установка тихо не происходила.

Решение:
- Префикс считается как всё до `bin/utunws` включительно → плоская раскладка payload.
- Проверка `runAsAdminOnMac().code !== 0` + верификация `isInstalled()` после установки.
- `elevation.ts`: `MacAdminResult` с флагом `cancelled` (osascript -128) и читаемым текстом.
- `ensureDataRoot`: источники дефолтных списков — runtime bundle, затем `/Library/.../default-lists`.
- `dirs.ts`: `resolveZapretRoot` ищет `bin/utunws` с учётом вложенного `Contents/Resources/Payload`.

Причина: `BrowserWindow` в `src/main/index.ts` создавалось с `frame: false` И

кнопки (App.tsx для macOS, base-page для Win/Linux) — единственные.

`isZapretInstalled` в `zapret-macos.ts`, диспетчер `zapret.ts`, IPC

### Fix CI "Fetch ZapretMac payload … exit 1" (commit 8b8a5af, в origin)
Причина: неаутентифицированные запросы к GitHub API из Actions бьются о rate-limit
(общий IP пул) → пустой `$URL` → `exit 1`. Локальный curl работал (релиз 1.1.2,
ассет `ZapretMac-macOS-universal.zip` на месте). Исправлено в build-macos.yml:
- обе API-шаги (`Resolve upstream tag`, `Fetch ZapretMac payload`) получили
  `env: GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` + заголовок Authorization Bearer;
- цикл retry ×5 с `sleep 15` + печать head ответа при пустом URL; `::error::` только
  после исчерпания попыток. Путь консистентен: воркфлоу копирует payload в
  `resources/macos/zapret`, electron-builder (to:'') делает плоско `resources/zapret`,
  `zapretBundleDir()` резолвит оба варианта.
- `gh` CLI на хосте НЕ установлен → триггер воркфлоу возможен только через GitHub UI
  (REST API: `POST /repos/<owner>/<repo>/actions/workflows/<file>/dispatches`,
  `{"ref":"macos-port"}`, токен из `git credential fill`).

### Fix CI bash "unexpected EOF while looking for matching ')'" (commit b41397f)
После добавления `}` в node-однострочник (`node -e "..."`) внутри bash
`$(...)` получили новую ошибку: парсер bash на runner (macOS) не смог сопоставить
`)` — хрупкая вложенность кавычек/скобок/регекса внутри `node -e "..."` внутри `$(...)`.
Локально в Git Bash воспроизвести НЕ удалось (там парсится), но на runner падает.
РЕШЕНИЕ (проверено локально симуляцией dedent-скрипта): вместо `node -e "..."` писать
скрипт в файл через heredoc `<<'NAME_EOF'` (`<<` без `-`, терминатор должен быть
в колонке 0 — GitHub Actions сам деденит `run:`-блок, как доказывает работающий
`python - <<'PY'` в шаге Install deps), затем `node /tmp/extract_*.js`. Тот же паттерн
для `Resolve upstream tag` и `Fetch ZapretMac payload`. НЕ использовать heredoc с
отступом-терминатором локально — bash его не найдёт (съест до EOF).
НЕ использовать `jq` без проверки — зависимость от раннера; node гарантирован (setup-node).

### Fix runtime «utunws did not stay running (1)» (commit a6128a1, в origin)
Причина (точно, по чтению upstream run.sh 1.1.2): запускаемый LaunchDaemon'ом
`run.sh` ЖЁСТКО завершается `exit 1`, если `$DATA_ROOT/lists` НЕ является
каталогом (line 71) ИЛИ любой из 8 файлов списков отсутствует (lines 74-78).
`install.sh` делает `kickstart` демона сразу и ждёт `utun50`; раз run.sh падает —
utun50 не появляется → install.sh пишет «utunws did not stay running» → exit 1.
Исходно `ensureDataRoot()` вызывался только внутри `startZapret`, ПОСЛЕ установки,
поэтому на шаге install.sh списков ещё не было.

Решение (в `runInstallFlow`, `src/main/core/zapret-macos.ts`):
- `ensureDataRoot('general-simple-fake')` ВЫЗЫВАЕТСЯ БЕЗУСЛОВНО в начале функции,
  до ветки `firstInstall`/`update`. Важно: неудачная установка оставляет
  `/Library/.../ZapretMac` (plist+bin), поэтому `isInstalled()` уже true и
  следующий клик идёт в ветку `update`, которая САМА не создавала lists.
- Ветка `update` теперь тоже делает `/bin/sh <INSTALL>/restart.sh`, чтобы
  установка оставляла РАБОТАЮЩИЙ демон даже после того broken-состояния.
- `general-simple-fake` безопасен: run.sh при невалидном/отсутствующем
  `selected-strategy` сам фолбэчит на него (lines 67-69), и .conf.in присутствует
  в bundle. Все 8 REQUIRED_LISTS есть в `resources/macos/zapret/default-lists`.

Проверка: `tsc --noEmit` (node+web) OK, `electron-vite build` OK.
Пуш `b714557..a6128a1` в origin/macos-port. Dispatch build-macos → run
33530111735 (in_progress, head a6128a1):
https://github.com/xdxdxdestra-svg/SlipgateFIX/actions/runs/33530111735

Для пользователя после нового .dmg: переустановить, `xattr -cr /Applications/Slipgate.app`,
Open Anyway, нажать «Установить Zapret» (теперь пройдёт — списки создаются ДО install.sh).
Если предыдущая неудачная попытка оставила файлы в /Library/Application Support/ZapretMac,
новый клик пойдёт по ветке update + restart.sh и тоже поднимет демон.

### Fix «Скопированный payload не содержит install.sh — обновите Slipgate» (commit 989309d)
Пользователь после .dmg a6128a1 увидел эту ошибку при нажатии «Установить Zapret»
(путь из встроенного payload). Причина: layout в .app — `Resources/zapret/` —
оказался НЕ плоским, а `copyDirRecursive` + плоская проверка `dest/install.sh`
это не учитывали. Реальная причина раскладки до конца не выяснена (CI Payload
полный и плоский, `extraResources to:''` должен флаттить), но сделал код
устойчивым к ЛЮБОЙ раскладке:
- `resolvePayloadRoot(base)` — ищет каталог с `bin/utunws`+`install.sh` (сам base,
  затем `Contents/Resources/Payload` и `Payload`).
- `flattenPayloadToRoot(dest)` — после копирования, если install.sh или
  bin/utunws глубже, вытаскивает их на верх dest (план Б).
- CI guard: `test -f resources/macos/zapret/install.sh` и `run.sh` — build
  падает сразу при неполном/вложенном Payload (раньше проверялся только
  bin/utunws + strategies.tsv с `|| find` фолбэком, что маскировало проблему).

### Диагностика «utunws не запустился за 15с» (тот же commit 989309d)
Пользователь прокликал дальше: install проходит (ensureDataRoot + списки ОК),
restart.sh возвращает 0, но `pgrep utunws` за 15с не находит процесс.
run.sh делает `kill -0 ENGINE_PID` и при отсутствии utun50 выходит 1 за ~10с.
Без логов не понять, что именно: нет GATEWAY_MAC, pf, карантин, битый payload
в /Library. Добавлен `collectZapretDiag()` который при неудаче собирает:
dataRoot/selected-strategy, pgrep utunws, последние 40 строк engine.log,
и launchctl print. Полная диагностика в лог Slipgate, в UI — хвост
engine.log (15 строк). Это даст точный ответ на следующей попытке.
